# Before the first public release

- [ ] Maintainer explicitly approves changing repository visibility.
- [ ] Verify that all authors/contributors can license their original code under MIT.
- [ ] Review source-specific media/data terms; do not label the research collection MIT.
- [ ] Keep raw movies, archives, private notes, tokens and local environments out of Git history.
- [ ] Check README, citation metadata, version and changelog.
- [ ] Run the clean-clone setup, checks, regression tests and website build.
- [ ] Verify hosted asset URLs/checksums and document unreachable source files.
- [ ] Check the English interface, desktop/mobile, video lifecycle and range exports.
- [ ] Set up maintainers' private security-report contact and GitHub reporting if available.
- [ ] Publish a reviewed tag/release; attach only material cleared for redistribution.

This list distinguishes a prepared software repository from a cleared research-data release.
